# novel-pane

在当前会话里开一个**可折叠的窗格**读书。`/novel <文件>` 打开，`/novel` 再敲一次收起。

按钮画在**窗格的第一行**，钉在那儿不动；正文在它下面滚；进度也钉在**提示框下面那一行**，看别处也看得到：

```
❯ 提示框
  卷轴 7800/20700 · 滚轮往下滚             ← 提示框下面那一行（引擎给插件钉字的地方）

┌ 试验小说.txt ──────────────────┐
│ [⇄ 卷轴] [↑] [↓] [⌂] [✕] 7800/20700 │  ← 窗格第一行：滚轮滚不动它
│ 第一章　夜航                        │
│                                    │
│ 船在雾里走，灯是唯一的方向。        │
│ …                                  │
└────────────────────────────────────┘
```

## 装

```
/plugin install novel-pane --marketplace zhuobichen/zhaowen-claudemod
```

## 用

**两条路，任选**：窗格（好看、不吃对话上下文，但要焦点或鼠标）与命令（永远能用，但每页会写进对话）。

### 命令这条路（不需要焦点，最稳）

在提示框里直接打——**按 ↑ 回车就是重复上一条，也就是"下一页键"**：

| 打什么 | 做什么 |
| --- | --- |
| `/novel <文件>` | 打开一本（相对路径按当前工作目录算）。**打开不说话**，只在失败时回一句 |
| `/novel n` | **下一页**，并把这一页打在对话里（↑⏎ 重复） |
| `/novel p` | 上一页 |
| `/novel 12` | 跳到第 12 页 |
| `/novel read` | 把当前页打出来，不动位置 |
| `/novel` | 窗格没开就打开上次那本（也不说话）；已开则收起 |

`/novel n` 在**新会话里**也管用：它会把上次读的那本重新打开再翻页。

### 窗格这条路（不吃对话上下文）

窗格**第一行**一排**按钮**，直接点就行——**不需要任何键盘焦点**：

```
[⇄ 卷轴] [↑] [↓] [⌂] [✕]  7800/20700
```

| 做什么 | 怎么做 |
| --- | --- |
| **两种模式** | 点 `⇄` 切换：**卷轴**（滚轮一行一行走）／**整屏**（滚轮一次一屏，靠 `↓` 也是）。按钮上的字就是当前模式，选的模式记在 store 里，下次还是它 |
| **滚动** | **鼠标滚轮**在窗格里滚，滚到书的结尾就停——没有人为的墙，也没有跳 |
| 进度怎么看 | 按钮右边就是 `7800/20700`；**提示框下面那一行**（`$.ui.status` 钉的）写得更全：`卷轴 7800/20700 · 滚轮往下滚`，整屏模式是 `整屏 第 3/84 页 · 52% · 点 ↓ 翻屏` |
| 一屏一屏走 | 点 `↓` / `↑`（每次一屏 = 窗格里**正文**的行数，不含控件那一行） |
| 从头开始 | 点 `⌂` |
| 收起 | 点 `✕`，或按 `Esc`（提示框下面那行也跟着消失） |
| **跳页** | 提示框里 `/novel 12` 跳到第 12 页（`/novel n` 下一页、`/novel p` 上一页、`/novel read` 原地看看） |

**✓ 控件怎么才不跟着滚（0.8.0 才做对）**：窗格那扇窗是**跟着内容滚**的，画在里面的东西一律跟着走——0.5.0 就是这么丢掉控件的。真正的解法是引擎文档里那句话：**"在自己画的行上面加一行表头的 hook，用 `e.by` 自己移行"**。也就是：

- 窗格**一次只画一屏**（表头一行 + 正文 `行数−1` 行），**树的永远只有窗口那么高**，所以那扇窗**根本没得滚**——控件不可能被滚走；
- 滚轮事件来了，mod **不交给引擎移窗**（`ui.scroll` 里返回 `{}`，不是 `next(e)`），而是**自己把读到哪加 `e.by` 行**再重画。

顺带一个好处：一次画 20 行而不是 1500 行，滚起来更省。

（`e.by` 缺了的时候用 `e.offset` 顶——插件自己调 `$.ui.scroll` 触发的那种事件只带目标位置。两条都没有时**原地不动**：把"读到哪"写进 `NaN` 会让窗格画成空白加一个 `NaN/60`，比不动糟得多。有一条测试盯着这个。）

**⚠️ 提示框上面那一行再也不要碰（0.6.0–0.7.0 的教训）**：那一行是**所有 mod 共用的一笔预算**（引擎给 `maxRows` 行），而且**插件的树是套在一起的**：后加载的插件在最内层，它的行就在**最上面**，而那一行的窗口**留着靠提示框的几行**。结果就是这个 mod 的行永远第一个被挤出去——不管它多短、跟别人排成一行也没用（别人在它的**外层**，它压根看不到别人）。所以 0.8.0 起这个 mod **一个字节都不往那行画**，余额、月相那些行照旧。

**进度为什么在提示框下面**：那是引擎给插件钉字的另一处（`$.ui.status`，每个插件一条，钉在引擎自己的通知旁边），**不在上面那笔预算里**，怎么变都不会挤到别人。

**位置的写盘是攒着的**：滚轮每动一格都写一次 store 太浪费，所以位置漂过 25 行才写一次；点按钮、跳页、收起时一定会写。

**读到哪儿是精确记的**：把 `e.by` 加到"读到哪"的那个行号就是，写回插件自己的 store——下次 `/novel` 从那一行接着往下。

**按钮上没有数字快捷键（故意的）**：提示框上面那一行的按钮支持「空提示框里按一个数字就触发」，但书开着的时候你就没法用 `1`~`5` 开头写一句话了（会被吃掉）。这个 mod 只给鼠标点，键盘走 `/novel n`。

（`Esc` 之外没有键盘快捷键：键盘要先进窗格才有，而给窗格抢焦点这件事本身就不稳——所以按钮和滚轮才是主路。）

### 书单：在窗格里点着换书（0.8.1）

书单是**一个目录里的文件**，不是一个写死的书。它**不进控件行**——`/novel shelf` 进，进去以后用鼠标点书名换：

| 做什么 | 怎么做 |
| --- | --- |
| 把书单摆进窗格 | `/novel shelf`（或 `/novel list` 只在对话里打一行） |
| 换一本看 | **点书名**（每本一行按钮；带 `•` 的是你读过、有进度的） |
| 换目录 | `/novel shelf <目录>`（记住，下次还是它）；`/novel list <目录>` 也一样记 |
| 回正文 | 点书名；或 `/novel shelf` 再敲一次（背后有书就退回那本） |

**书单看哪个目录**：你指定过的那个；没指定过就是当前这本书所在的目录；连书都没开过就是上一次那本所在的目录。

**只列能读的**：`.txt .md .markdown .text .log`——目录、图片、压缩包不列（点开只会是一屏乱码）。书名按拼音排序（`甲` 在 `乙` 前），不是码点序。

**⚠️ 为什么书单不做成控件行上的一个按钮（0.9.0 的教训）**：控件行画在窗格**里面**，窗格由引擎停靠在对话右边、宽度它定（`$.ui.open` 的 `columns` 是停靠宽度、`rows` 是内联高度）——**比窗格宽的行会被裁，被裁的按钮就点不着**。0.9.0 往那一行加了个按钮（还带双宽 emoji），整行从 35 格涨到约 43 格，随后窗格就不再好好停在右侧了。0.8.1 把那一行**原样退回**，书单改用命令进、列表里点。列表里的长文件名也会按窗格宽度裁（按钮的宽度就是它标签的宽度，不裁会把整棵树撑宽）。

### 两条路的取舍

- **命令式**每打印一页，这一页就**进了对话上下文**（也会计入费用）——看两眼很顺手，长时间通读会堆。
- **窗格**里的文字是画上去的，**不进对话**——通读用它，配鼠标点击最省事。

## 几件要知道的

- **单文件上限 4 MiB**：书是用 `$.fs.read` 读的，超过 4 MiB 会被引擎拒绝（那时会提示"读不到这个文件"，不会开一个空窗格）。
- **Markdown 原样显示**：`ebook-library/books` 里那些 `.md` 技术书能读，但 `#`、代码块这些标记会照原样出现在窗格里，不做渲染。
- **中文按两个格子折行**：宽度是按终端单元格算的（汉字 2、拉丁字符 1），所以不会每行溢出。
- **书不在窗格里**：`Client` 的 props 上限 10 万字符，一本书塞不进去——文本留在 hooks 模块，每次只把当前这一页递给窗格。

## 文件

```
.claude-plugin/plugin.json  名字、版本、类型契约的位置
hooks/hooks.json            模块清单
hooks/register.tsx          /novel、读文件、记住位置、画窗格（表头+一屏正文）、滚轮自己移行、钉进度那行
hooks/paging.ts             折行、分页、一屏取多少行、按键、进度、按钮与钉的那行（纯函数，测试盯的就是它）
types/index.d.ts            $.state / Page 的类型契约
tests/paging.test.ts        31 条：宽度、折行、分页、每个键、边界、一屏几行、两种模式、钉的那行说什么
tests/pane.test.tsx         24 条：真的打开并画出来、画出来的**正好一屏高**（高一行那扇窗就有得滚了）、
                            被要求移窗时移的是正文而不是窗（控件留在一屏里）、
                            没带距离的移动不会把"读到哪"变成 NaN（空窗格 + NaN/60）、
                            点按钮翻页/回开头/收起（整条链）、打开不说话、
                            提示框上面那一行一个字节都不画、读到哪按行记住、读不到会说、不给参数会说怎么用
```

**⚠️ 窗格里不能有任何 import**——连 `import type` 都不行。实测：带类型导入时窗格里**什么都不画**（元素在树上、内容为空、哪里都不报错），把类型内联掉、去掉 import 就正常。hooks 模块（register.tsx）不受这条限制。0.3.0 起这个 mod 不再用 `Client` 了（按键要焦点，不稳），这条踩过的坑留着给下一次用 `Client` 的时候。
