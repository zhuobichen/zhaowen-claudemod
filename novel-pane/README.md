# novel-pane

在当前会话里开一个**可折叠的窗格**读书。`/novel <文件>` 打开，`/novel` 再敲一次收起。

按钮在**提示框上面那一行**（跟别的 mod 共用同一行），进度钉在**提示框下面那一行**，正文在窗格里：

```
[⇄ 卷轴] [↑] [↓] [⌂] [✕]                 ← 提示框上面那一行，跟别的 mod 挤在一起
❯ 提示框
  卷轴 7800/20700 · 滚轮往下滚             ← 提示框下面那一行（引擎给插件钉字的地方）

┌ 试验小说.txt ──────────────┐
│ 第一章　夜航                │
│                            │
│ 船在雾里走，灯是唯一的方向。│
│ 他把书翻到下一页，风从舷窗进来。│
│ …                          │
└────────────────────────────┘
```

## 装

```
/plugin install novel-pane --marketplace zhuobichen/zhaowen-claudemod
```

## 用

**两条路，任选**：窗格（好看、不吃对话上下文，但要焦点或鼠标）与命令（永远能用，但每页会写进对话）。

### 命令这条路（不需要焦点，最稳）

在提示框里直接打——**按 ↑ 回车就是重复上一条，也就是"下一页键"**：

| 打什么 | 做什么 |
| --- | --- |
| `/novel <文件>` | 打开一本（相对路径按当前工作目录算）。**打开不说话**，只在失败时回一句 |
| `/novel n` | **下一页**，并把这一页打在对话里（↑⏎ 重复） |
| `/novel p` | 上一页 |
| `/novel 12` | 跳到第 12 页 |
| `/novel read` | 把当前页打出来，不动位置 |
| `/novel` | 窗格没开就打开上次那本（也不说话）；已开则收起 |

`/novel n` 在**新会话里**也管用：它会把上次读的那本重新打开再翻页。

### 窗格这条路（不吃对话上下文）

提示框**上面那一行**一排**按钮**，直接点就行——**不需要任何键盘焦点**：

```
[⇄ 卷轴] [↑] [↓] [⌂] [✕]
```

| 做什么 | 怎么做 |
| --- | --- |
| **两种模式** | 点 `⇄` 切换：**卷轴**（往下一直滚）／**整屏**（一次一屏，靠 `↓`）。按钮上的字就是当前模式，选的模式记在 store 里，下次还是它 |
| **卷轴滚动** | **鼠标滚轮**在窗格里滚——**滚不到头**：一次画约 1500 行，快滚到底时整块悄悄重设到你现在的位置、窗口同时回到新块的顶部，**画面内容不变**，所以既不会撞墙也不会跳一下 |
| 进度怎么看 | **提示框下面那一行**（`$.ui.status` 钉的）：`卷轴 7800/20700 · 滚轮往下滚`，滚轮每动一下就跟着变；整屏模式那行是 `整屏 第 3/84 页 · 52% · 点 ↓ 翻屏` |
| 一屏一屏走 | 点 `↓` / `↑`（每次一屏 = 窗格可见的行数） |
| 从头开始 | 点 `⌂` |
| 收起 | 点 `✕`，或按 `Esc`（进度那行也跟着消失） |
| **跳页** | 提示框里 `/novel 12` 跳到第 12 页（`/novel n` 下一页、`/novel p` 上一页、`/novel read` 原地看看） |

**✓ 进度不跟着滚（0.6.0 改的）**：0.5.0 之前控件画在窗格**里面**——窗格那扇窗是**跟着卷轴滚**的，所以往下读几屏，控件就滚出屏幕外没了。窗格没有"钉住的顶栏"这种东西，所以控件搬到了提示框外面。

**⚠️ 控件只占一行，而且是跟别人共用的一行（0.7.0 改的）**：提示框上面那一行的**行数是所有 mod 共用的**（引擎给一个 `maxRows` 预算），谁多画一行，别人就被挤出可视窗口。0.6.0 那版把按钮和一大串说明都摊在那儿，一行**折成了两行**，于是把余额、月相那两行挤掉了。现在按钮只有五个短标签，并且跟别人画的内容**排在同一行**（自己那截 `flexShrink: 0` 占住约 25 格，别人的内容自己缩），行数不变。

**进度为什么去了提示框下面**：那一行是引擎给插件钉字的地方（`$.ui.status`，每个插件一条，钉在引擎自己的通知旁边），**不占提示框上面那行的预算**，所以怎么变都不会挤到别人。

**位置的写盘是攒着的**：滚轮每动一格都写一次 store 太浪费，所以位置漂过 25 行才写一次；点按钮、跳页、收起时一定会写。

**读到哪儿是精确记的**：窗格窗口滚到哪一行，那个行号就是"读到哪"，写回插件自己的 store——下次 `/novel` 从那一行接着往下，不是从那一屏的开头。

**按钮上没有数字快捷键（故意的）**：那一行的按钮支持「在空提示框里按一个数字就触发」——但那样一来，书开着的时候你就没法用 `1`~`5` 开头写一句话了（会被吃掉去翻页）。所以这个 mod 只给鼠标点，键盘走 `/novel n`。

（`Esc` 之外没有键盘快捷键：键盘要先进窗格才有，而给窗格抢焦点这件事本身就不稳——所以按钮和滚轮才是主路。）

### 两条路的取舍

- **命令式**每打印一页，这一页就**进了对话上下文**（也会计入费用）——看两眼很顺手，长时间通读会堆。
- **窗格**里的文字是画上去的，**不进对话**——通读用它，配鼠标点击最省事。

## 几件要知道的

- **单文件上限 4 MiB**：书是用 `$.fs.read` 读的，超过 4 MiB 会被引擎拒绝（那时会提示"读不到这个文件"，不会开一个空窗格）。
- **Markdown 原样显示**：`ebook-library/books` 里那些 `.md` 技术书能读，但 `#`、代码块这些标记会照原样出现在窗格里，不做渲染。
- **中文按两个格子折行**：宽度是按终端单元格算的（汉字 2、拉丁字符 1），所以不会每行溢出。
- **书不在窗格里**：`Client` 的 props 上限 10 万字符，一本书塞不进去——文本留在 hooks 模块，每次只把当前这一页递给窗格。

## 文件

```
.claude-plugin/plugin.json  名字、版本、类型契约的位置
hooks/hooks.json            模块清单
hooks/register.tsx          /novel、读文件、记住位置、画窗格、画提示框上面那排按钮、钉进度那行
hooks/paging.ts             折行、分页、按键、进度、分块、按钮与钉的那行（纯函数，测试盯的就是它）
types/index.d.ts            $.state / Page 的类型契约
tests/paging.test.ts        33 条：宽度、折行、分页、每个键、边界、无限卷轴、两种模式、
                            按钮那一行有多宽、钉的那行说什么
tests/pane.test.tsx         21 条：真的打开并画出来、控件在提示框那一行（不在窗格里）、
                            打开不说话、按钮跟别人共用一行、钉的行跟着按钮走、
                            点按钮翻页/回开头/收起（整条链）、读不到文件会说、不给参数会说怎么用
```

**⚠️ 窗格里不能有任何 import**——连 `import type` 都不行。实测：带类型导入时窗格里**什么都不画**（元素在树上、内容为空、哪里都不报错），把类型内联掉、去掉 import 就正常。hooks 模块（register.tsx）不受这条限制。0.3.0 起这个 mod 不再用 `Client` 了（按键要焦点，不稳），这条踩过的坑留着给下一次用 `Client` 的时候。
