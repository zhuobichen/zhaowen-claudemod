# moon-band

提示行上面一行月光：**月相 + 月龄 + 一句古诗**，整行压暗。纯装饰，`/moon` 可以收起来。

```
🌒 娥眉月 4.6天 · 「今人不见古时月，今月曾经照古人。」李白《把酒问月》
```

## 月相与月龄是从哪来的（这段重要）

**月相名**：不是用"平均朔望月"糊出来的。实测：经典的平均公式拿 2026 年 10 月的四个相时刻去对，误差最大到 **−0.72 天**（近 17 小时）；就算把锚点换成 10-10 那次新月、再扫周期参数，最坏误差仍有 **0.75 天**——因为月亮走得本来就不匀，两参数模型不可能更准。而**背错 Meeus 的系数表**会得到一个"看着挺准其实全错"的月亮，那更糟。

所以用的是**一张相时刻表 + 相邻两时刻线性插值**：

- 数据来源：StarWalk 月相日历、香港天文學會 2026 年月相表（两处一致，差 ±1 分钟），北京时间
- 覆盖 **2026-10-03 → 2026-12-31**（13 个时刻，严格四相轮转，间隔 6.7–8.2 天，朔望月 29.63/29.74 天）
- 表内：**准到分钟**（相位在两时刻之间按线性推进，所以离边界几小时内的相名可能有几小时的出入）
- 表外：退回平均朔望月推算，并且**行首显示 `≈`**，告诉你这是个估计，不装成事实

**月龄**：是**距上一次新月的真实天数**，不是"相位占比 × 平均月长"。后者会把月龄算小——这个朔望月偏长（新月→上弦 8.0 天），占比算法今天会报 4.2 天，而农历是 4.6 天。**农历日期是你能自己核的**，所以这个数必须对得上它。

要延长覆盖，就往 `hooks/moon.ts` 的 `INSTANTS` 里**整段**追加相时刻（必须保持四相轮转、不可乱序，新月靠"从第一项起每第四项"定位——有一条测试盯着这个）。表是给 `2026-10-03` 起的连续四相用的，中间**不能跳**。

## 那句诗

**每分钟换一句，从一个 46167 句的库（随 mod 一起分发）里挑，一轮不重复。**

库在 `data/poems.txt`：唐诗 3 万句 + 宋词 1.6 万句，每行 `诗句<TAB>作者《篇名》`，3.18 MiB（`$.fs.read` 的硬上限是 4 MiB）。来源与生成方式见 `data/NOTICE.md`，复现脚本在仓库根的 `tools/build_poems.py`。

**怎么做到"轮完一遍才回头"**：用一条**满周期线性同余**——`index = (step * slot + offset) mod N`，其中 `step` 与 `N` 互质。这是个双射，所以连续 N 个格子会**把每一句都取到一次、且只取一次**，走完 N 格才重复；`step`/`offset` 每个周期重新取，所以下一轮是另一种顺序，不是同一轮重播。

- 46167 句 / 每分钟一句 → **一轮约 32 天**
- 同一分钟内不变（画面之间跳句没法读）
- 一个周期内，**相邻两分钟不会是同一句**（step 与 N 互质且不等于 1）
- 周期交界处理论上可能与前一句相同（概率 1/N，可忽略）

读数不靠状态：`$.store` 里只存"要不要显示"这一个开关。

### 想换库

`data/poems.txt` 每行 `诗句<TAB>来源` 即可，缺一半的行、重复的句子会被丢掉。**注意 4 MiB 上限**（超了 `$.fs.read` 直接拒绝，mod 会退回内置 8 句并在屏幕上弹一句提示——不会假装在用你的库）。

内置那 8 句只在库读不到时兜底：李白《把酒问月》/《月下独酌》/《静夜思》、张九龄《望月怀远》、张若虚《春江花月夜》、王维《竹里馆》、苏轼《水调歌头》、李商隐《嫦娥》。

## 图标

用 emoji 月相（🌑🌒🌓🌔🌕🌖🌗🌘，八相一一对应）。渲染不好就换单色字形一族（`◐◑◒◓` 那套），改 `hooks/moon.ts` 的 `GLYPHS` 一行。

## 和别的 meter 共存

它挂在 `ui.render{component:'AbovePrompt'}`，和 Context View、deepseek-balance 是同一个位置。所以它 `await next(e)` 把下层画的树**包住**再画自己那行——直接返回自己的树会把别人那行吞掉。

## 开关

`/moon` 收起／放回，记在 `$.store` 里，跨会话保留。
